# 同一个项目中的技能与种族示例

所有示例根包：`com.example.tensuraaddon.example`。模组入口是 `com.example.tensuraaddon.TensuraAddon`，默认命名空间为 `tensura_addon`。复制脚本会一起更改这些位置。

## 从哪个文件开始看

1. `ExampleContent.java`：决定是否把整组示例注册到游戏。
2. `registry/ExampleSkills.java` 与 `registry/ExampleRaces.java`：所有类如何进入 ManasCore 注册表。
3. `skill/ExampleSkill.java`：共用的图标、获取条件、服务端检查、能量与冷却处理。
4. 各类型技能类：不同效果如何落到对应回调。
5. `race/ExampleRace.java` 与 `race/ExampleEvolvedRace.java`：种族如何引用技能并连成进化路线。

示例默认不自动根据 EP 发放技能，也不修改 Tensura 的初始／随机转生列表。启用示例注册后，可用主模组已有的管理功能测试；正式获取方式应按自己的模组设计接入。

## 六种技能的写法

### 抗性：修改已有伤害

`ExampleResistanceSkill` 使用 `SkillType.RESISTANCE`。在 `onTakenDamage` 内通过伤害标签判断火焰，再修改 `Changeable<Float>` 中的数值。示例乘数为 `0.8`。

返回 `true` 表示继续处理修改后的伤害。不要为实现减伤再调用一次 `hurt`；返回 `false` 则属于取消伤害。

### 内在／固有：被动与种族关联

`ExampleIntrinsicSkill` 使用 `SkillType.INTRINSIC`。`canTick` 开启回调，`onTick` 每秒在服务端检查一次，在水中补充空气并调用框架熟练度接口。

`ExampleRace.getIntrinsicSkills` 返回 `ExampleSkills.INTRINSIC.get()`，展示种族固有技能如何引用同一个项目中的注册对象。技能的 `SkillType` 是分类；种族的固有技能列表是种族与技能的关联位置。

### 普通：一次主动施放

`ExampleCommonSkill` 使用 `SkillType.COMMON`。先判断生命值是否需要恢复，再调用公共 `tryStart`；成功后恢复 2 点生命，设置 60 tick 冷却，并增加熟练度。魔素消耗示例为 10。

公共流程的顺序是：服务端及有效模式检查 → 冷却检查 → 能量检查并扣费 → 施放效果 → 冷却与熟练度。

### 额外：可开关的持续效果

`ExampleExtraSkill` 使用 `SkillType.EXTRA`。通过 `canBeToggled` 暴露开关，以 `instance.isToggled()` 判断是否生效。每 100 tick 在需要治疗时消耗 5 魔素，恢复 1 点生命；资源不足则关闭实例开关。

开关属于每个持有者的 `ManasSkillInstance`。技能注册对象是单例，不应把某个玩家的开关、计时或目标直接存入该单例的普通字段。

### 独特：多模式

`ExampleUniqueSkill` 使用 `SkillType.UNIQUE`。`getModes` 返回 2；`getModeId` 把模式映射为 `example_unique_speed` 和 `example_unique_guard`。分别示范加速与抗性效果、10/20 魔素消耗、80 tick 的各自冷却。

模式编号从 0 开始，`keyNumber` 与 `mode` 是不同参数。新增模式时同步修改数量、模式 ID、效果分支与模式语言键。

### 究极：范围与目标筛选

`ExampleUltimateSkill` 使用 `SkillType.ULTIMATE`。服务端查询附近实体，再按存活、队友关系和真实距离筛选，对自身与 6 格内的友方施加恢复效果。

一次施放消耗 40 魔素，设置 200 tick 冷却。扣费与熟练度放在目标循环外，避免按目标数量重复结算。

上述数值与效果用于演示接口。技能等级由 `SkillType` 指定，主动、被动、持续、多模式或范围写法可按自己的设计组合。

## 种族：一套基础 → 进化示例

`ExampleRace` 注册为 `tensura_addon:example_race`：

- `getBaseAuraRange` / `getBaseMagiculeRange` 给出初始能量范围。
- 构造器中的 `addAttributeModifier` 示范最大生命值修饰。
- `getIntrinsicSkills` 引用内在技能。
- `getNextEvolutions` 与 `getDefaultEvolution` 指向进化种族。

`ExampleEvolvedRace` 注册为 `tensura_addon:example_evolved_race`：

- `getPreviousEvolutions` 指回基础种族。
- 固有技能列表保留内在技能，并加入抗性技能。
- `getEvolutionRequirements` 给出基础最大 EP 4000 和内在技能熟练两项条件，每项权重 50，总和 100。

条件写在**目标种族**上。示例使用 Tensura 已有的 `EPRequirement` 与 `AbilityRequirement`，不另建进化状态系统。`LinkedHashMap` 保持界面条件的展示顺序。

两种族使用 `TensuraRace` 默认的能量初始化与进化处理。基础数值、属性修饰和条件都在对应源码中；技能的注册对象只在运行时方法内 `.get()`，避免种族构造期间跨注册表取值。

## 新增自己的技能或种族

复制最接近的类，修改类名与注册名，在现有注册器中增加一个 `DeferredHolder`。为新 ID 添加语言与图标，然后按需要调整 `ExampleContent` 中的注册接入。

资源位置与命名约定：

| 内容 | 示例 |
| --- | --- |
| 技能注册 ID | `tensura_addon:example_unique` |
| 技能名称键 | `tensura_addon.skill.example_unique` |
| 技能描述键 | `tensura_addon.skill.example_unique.description` |
| 模式名称键 | `tensura_addon.skill.mode.example_unique_speed` |
| 技能图标 | `assets/tensura_addon/textures/skill/example_unique.png` |
| 种族名称键 | `tensura_addon.race.example_race` |
| 种族图标 | `assets/tensura_addon/textures/gui/sprites/icons/races/example_race.png` |

中英文语言文件均已提供，说明文本保留空值，图标为透明占位。正式制作时替换为自己的名称、文案与图片。

## 已按当前依赖核对的细节

- `ManasSkillInstance.setCoolDown(ticks, mode)`：第一个参数是 tick，第二个是模式。20 tick 为 1 秒。
- 当前 Tensura 2.0.0.1 的 `isOutOfEnergy` 在能量足够时**同时扣除能量**。`getMagiculeCost` 本身只返回消耗值，不负责扣费。
- 注册使用 `SkillAPI.getSkillRegistryKey()` / `RaceAPI.getRaceRegistryKey()` 与 NeoForge `DeferredRegister`。
- 这些接口来自项目自带的 Tensura 2.0.0.1 / ManasCore 4.0.0.0 JAR；升级前置时应再次核对。

写法参考了现有附属的注册与回调模式，并按上述实际版本核对。五个参考项目只读，不作为本项目构建时的绝对路径依赖。
